Short answer: there is a real backend, but it isn't a separate server, and there's no real database. The backend runs inside the Next.js app, and users and orders are saved to a JSON file on disk. That was deliberate, to keep setup to one command, but it's the main limitation to know about.

## Tech stack

| Layer | What we used |
|---|---|
| Framework | **Next.js 16** (App Router), frontend and backend in one app |
| UI | **React 19**, **TypeScript** |
| Styling | **Tailwind CSS v4**; the theme lives in one place, `src/app/globals.css` |
| Font | Plus Jakarta Sans, served by Next.js itself |
| Auth | **bcryptjs** for password hashing, **jose** for signed login-session cookies |
| Data | Product catalogue: 194 real sample products with images and reviews from **DummyJSON**, stored in the repo as `data/products.json` |
| Storage | **JSON file** `data/db.json` for users and orders; the browser's own storage for cart and wishlist |

## Is there a backend?

Yes, built into the same Next.js app:
- **Server-rendered pages:** the home, search, product and order pages are built on the server, and searching and filtering the catalogue happen there.
- **Server-side actions:**
  - `app/actions/auth.ts` handles sign-up, sign-in and sign-out. Passwords are hashed with bcrypt, and the session is a signed cookie that the page's JavaScript can't read.
  - `app/actions/orders.ts` places orders. It checks you're signed in, validates the address, and **recalculates every price from the catalogue**, so the browser can't tamper with totals.
- **API endpoint:** `GET /api/suggest` powers the search suggestions.

## Is a database connected?

**No.** Here's where each kind of data lives:

| Data | Where it lives | Implication |
|---|---|---|
| Products | `data/products.json` (read-only) | Fine for a demo |
| Users, orders | `data/db.json`, created on first sign-up and kept out of git | Works on your PC or any normal server; **would be lost on a hosting platform like Vercel**, which doesn't keep files between requests |
| Cart, wishlist | Browser storage | Survives reloads, but doesn't follow you to another device |

All database access goes through one file, `src/lib/db.ts`, so moving to a real database (Supabase/Postgres or SQLite) only means rewriting that file. That's the first thing to do before deploying.
